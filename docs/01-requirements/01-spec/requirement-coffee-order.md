# Requirement: ระบบรับออเดอร์ร้านกาแฟ

## บริบท (Background)

เราเป็นผู้ประกอบการที่ต้องการเปิดร้านกาแฟ และต้องการ "ตัวช่วยในการรับ Order จากลูกค้า" เพื่อลดภาระพนักงานหน้าร้านในการจดออเดอร์ด้วยมือ ลดความผิดพลาด และทำให้ลูกค้าสั่งเครื่องดื่มได้สะดวกขึ้น

## กลุ่มผู้ใช้งาน (User Roles)

- **ลูกค้า (Customer)** — ผู้ที่มาสั่งเครื่องดื่ม/ของทานเล่นที่ร้าน
- **พนักงาน/เจ้าของร้าน (Staff)** — ผู้รับออเดอร์ ชงเครื่องดื่ม และจัดการคิวออเดอร์

## ขอบเขต (Scope)

**สิ่งที่ทำ (In Scope)**
- ลูกค้าดูเมนูและสั่งเครื่องดื่ม/ของทานเล่นได้ด้วยตนเอง
- ลูกค้าเลือกประเภทออเดอร์ (ทานที่ร้าน/รับกลับบ้าน) และปรับแต่งเครื่องดื่ม (ความหวาน, ชนิดนม, ขนาดแก้ว)
- พนักงานเห็นรายการออเดอร์ที่เข้ามาแบบเรียลไทม์ และอัปเดตสถานะออเดอร์ได้ (รับออเดอร์ / กำลังทำ / เสร็จแล้ว)
- ลูกค้าชำระเงินและได้รับแจ้งเตือนเมื่อออเดอร์เสร็จ

**สิ่งที่ไม่ทำ (Out of Scope)**
- ระบบจัดการสต็อกวัตถุดิบ/คลังสินค้า
- ระบบบัญชี รายงานภาษี
- การจัดส่งเดลิเวอรีนอกร้าน (delivery aggregator)
- ระบบสมาชิก/สะสมแต้ม

## Epics

| ID | Epic | คำอธิบาย |
|----|------|----------|
| E1 | เมนูและการสั่งซื้อของลูกค้า | ลูกค้าดูเมนู เลือก ปรับแต่ง และยืนยันออเดอร์ |
| E2 | การจัดการออเดอร์ของร้าน | พนักงานเห็นและอัปเดตสถานะออเดอร์ที่เข้ามา |
| E3 | การชำระเงิน | ลูกค้าชำระเงินก่อนออเดอร์เข้าคิวครัว |
| E4 | การแจ้งเตือนสถานะออเดอร์ | ลูกค้าทราบว่าออเดอร์ถึงคิวไหน/เสร็จแล้วหรือยัง |

## กฎทางธุรกิจ (Business Rules)

1. ออเดอร์ที่ยังไม่ชำระเงินจะไม่ถูกส่งเข้าคิวครัว
2. ลูกค้าต้องเลือกประเภทออเดอร์ (ทานที่ร้าน/รับกลับบ้าน) ก่อนยืนยันออเดอร์เสมอ เพราะกระทบลำดับการจัดคิว
3. ราคาที่แสดงต่อลูกค้าเป็นราคารวมภาษีแล้ว
4. ออเดอร์ที่ยกเลิกได้เฉพาะก่อนพนักงานกดรับออเดอร์เท่านั้น
